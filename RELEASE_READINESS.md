# Prontidão para distribuição pública

**Estado da auditoria (2026-10-02): pronto para publicar v171.2.0; isolamento por UID confirmado nas regras ativas e em 79 verificações locais.** A v171.2.0 publicará a importação local de jogos Pokémon integrada pelo PR #7 (`a4e5a3f`), além do fluxo de assinatura opcional. A release anterior v171.1.0 passou nos workflows Windows de PR e release (runs `36955572832` e `36955753712`). A publicação atual exige novamente os checks do PR e o build da tag.

## Pronto para distribuição

- A v171.1.0 fornece `pokemon-play-win-x64-portable.zip` (62.393.080 bytes; SHA-256 `0beb411e25fd4a120a94bfca7576f5ae0d4eff0d0fb74a991748c5b6980c1787`) para primeira instalação e `pokemon-play-win-x64-update.zip` (62.390.410 bytes; SHA-256 `433aa0ce0caa0d552777021422f779ee5a601579691f128f9edc2cb3ac53d833`) para o atualizador.
- O pacote atual é compilado de forma reproduzível no workflow Windows, verifica a ausência de marcadores do segredo OAuth no assembly principal e inclui sidecars SHA-256.
- O código novo usa OAuth com PKCE e não envia `client_secret`. Jogos, ROMs, BIOS e emuladores de terceiros não são empacotados.
- No `main`, **Adicionar jogos** permite selecionar arquivos ou pastas, identificar jogos Pokémon compatíveis, marcar hack ROMs e manter os arquivos no caminho local escolhido pelo usuário. A funcionalidade não envia nem inclui ROMs no pacote. A release v171.1.0 não contém essa funcionalidade ainda. O executável legado com biblioteca de jogos permanece no computador do proprietário; releases públicas continuam sem ROMs, BIOS ou emuladores de terceiros.
- A autenticação GitHub disponível permite publicar no repositório, mas o token não é conhecido nem deve ser copiado para arquivos ou para o chat. O workflow de release usa o `GITHUB_TOKEN` temporário do Actions.

## Condições auditadas para abrir o repositório

1. **Asset legado v1.0.0:** a release contém `Pokemons.Play.exe` (837.331.686 bytes; SHA-256 `26e450375e75b229f5c97855765987b1cc8e1aaa9f78f5a6bd77ea7735f5aa15`). O digest coincide com o bundle descrito em `recovered-source/README.md`. O arquivo não está versionado na branch nem nas referências Git atuais; existe apenas como anexo da release v1.0.0. A pedido do proprietário, a release foi convertida em rascunho em 2026-10-02; o asset foi preservado e não deve aparecer na distribuição pública. O executável legado continua no computador do proprietário. Releases públicas não devem incluir o pacote com ROMs; o `main` oferece importação local de arquivos/pastas.
2. **Segredo OAuth legado:** o cliente **Pokemons Play para Windows** é do tipo **Computador**. A versão nova usa PKCE e não envia `client_secret`. O proprietário confirmou que o único segredo ativo deve permanecer ativo por enquanto; ele não será rotacionado nesta etapa. O segredo não entra no código nem nos pacotes públicos novos, e a release antiga que continha o bundle está em rascunho. Não excluir o cliente OAuth, pois isso também invalidaria o ID usado pelo fluxo atual.
3. **Regras do Firestore:** o Firebase MCP autenticado confirmou as regras ativas do banco `(default)` em `southamerica-east1`: acesso somente com autenticação e `request.auth.uid == userId` na subárvore `/users/{userId}`. O snapshot passou em 79 verificações no emulador oficial com dois UIDs simulados e acesso anônimo, incluindo leitura/escrita/listagem, manifests, chunks, claims e campos falsificados. Nenhuma regra ou dado de produção foi alterado. A leitura REST anônima anterior respondeu `403 PERMISSION_DENIED`. As regras não validam esquema/tamanho dentro da subárvore do próprio usuário; essa limitação está registrada em [FIRESTORE_AUDIT.md](FIRESTORE_AUDIT.md), com o hash do snapshot, escopo e comando reproduzível.
4. **Assinatura Authenticode/App Control:** a assinatura fica para uma etapa futura, conforme decisão do proprietário. O workflow permite pacote sem assinatura e assina/verifica automaticamente quando os secrets `POKEMONPLAY_SIGNING_PFX_BASE64` e `POKEMONPLAY_SIGNING_PFX_PASSWORD` forem configurados. Distribuições não assinadas podem exibir alertas do SmartScreen. Este Windows bloqueia DLLs não assinadas sob política User Mode Code Integrity em modo enforced; um administrador do dispositivo precisa aprovar o certificado/editor para permitir execução aqui. Não desative a política.

Próximos passos de publicação: confirmar os checks do PR, gerar a release atualizada v171.2.0, verificar seus assets, tornar o repositório público e testar o download sem autenticação. A release v1.0.0 deve permanecer em rascunho, preservando o bundle legado fora da distribuição pública.
