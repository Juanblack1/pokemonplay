# Prontidão para distribuição pública

<!-- public-release-status: blocked -->

**Estado da auditoria (2026-10-02): não tornar o repositório público ainda.** O repositório `Juanblack1/pokemonplay` está privado. A release v171.1.0 é a versão mais recente; os workflows Windows de PR e release passaram (runs `36955572832` e `36955753712`). O `main` já contém a importação local de jogos Pokémon, integrada pelo PR #7 (`a4e5a3f`); essa mudança foi validada no CI (`37013531608`), mas ainda não foi publicada em uma nova release.

## Pronto para distribuição

- A v171.1.0 fornece `pokemon-play-win-x64-portable.zip` (62.393.080 bytes; SHA-256 `0beb411e25fd4a120a94bfca7576f5ae0d4eff0d0fb74a991748c5b6980c1787`) para primeira instalação e `pokemon-play-win-x64-update.zip` (62.390.410 bytes; SHA-256 `433aa0ce0caa0d552777021422f779ee5a601579691f128f9edc2cb3ac53d833`) para o atualizador.
- O pacote atual é compilado de forma reproduzível no workflow Windows, verifica a ausência de marcadores do segredo OAuth no assembly principal e inclui sidecars SHA-256.
- O código novo usa OAuth com PKCE e não envia `client_secret`. Jogos, ROMs, BIOS e emuladores de terceiros não são empacotados.
- No `main`, **Adicionar jogos** permite selecionar arquivos ou pastas, identificar jogos Pokémon compatíveis, marcar hack ROMs e manter os arquivos no caminho local escolhido pelo usuário. A funcionalidade não envia nem inclui ROMs no pacote; é necessário selecionar arquivos próprios para jogar. A release v171.1.0 não contém essa funcionalidade ainda.
- A autenticação GitHub disponível permite publicar no repositório, mas o token não é conhecido nem deve ser copiado para arquivos ou para o chat. O workflow de release usa o `GITHUB_TOKEN` temporário do Actions.

## Bloqueios antes de abrir o repositório

1. **Asset legado v1.0.0:** a release contém `Pokemons.Play.exe` (837.331.686 bytes; SHA-256 `26e450375e75b229f5c97855765987b1cc8e1aaa9f78f5a6bd77ea7735f5aa15`). O digest coincide com o bundle descrito em `recovered-source/README.md`. A auditoria confirmou que o arquivo não está versionado na branch nem nas referências Git atuais; ele existe como anexo da release v1.0.0. `recovered-source/tools/extract_payload.py` declara que o bundle contém imagens ROM protegidas e deliberadamente as omite. A v171.1.0 contém somente o launcher e o runtime; para jogar nessa versão, a pessoa precisa configurar os próprios arquivos de jogo e emuladores compatíveis. O `main` agora oferece importação local, sem distribuir ROMs no novo pacote. Mesmo que ROMs possam ser encontradas publicamente, isso por si só não documenta autorização de redistribuição do asset legado; consulte a [orientação oficial da Nintendo sobre cópias de jogos e ROMs](https://en-americas-support.nintendo.com/app/answers/detail/a_id/55888/~/intellectual-property-%26-piracy-faq). O asset permanece anexado conforme a preferência do proprietário, mas o repositório precisa continuar privado até que haja licença documentada ou o proprietário autorize e conclua outra solução adequada para esse anexo.
2. **Segredo OAuth legado:** versões anteriores do bundle distribuíram um `client_secret`. A sessão autenticada no Google Cloud confirmou o cliente **Pokemons Play para Windows** e seu tipo **Computador**, correspondente ao `client_id` do código. A v171.1.0 usa PKCE e envia apenas `client_id` e `code_verifier`; não depende de segredo. A chave antiga ainda precisa ser desativada no Console pelo proprietário antes da abertura pública. Não exclua o cliente OAuth, pois isso também invalidaria o ID usado pelo fluxo atual. A rotação ainda não foi executada.
3. **Regras do Firestore:** confirmar no projeto Firebase que as regras do servidor limitam leitura e gravação ao UID autenticado. O código organiza documentos por UID, mas as regras implantadas não estão neste repositório. A sessão autenticada recebeu do Firebase Console a mensagem de que o projeto não existe ou a conta não tem permissão para listar apps; a lista de bancos no Cloud Console retornou erro do servidor sem linhas. Portanto, as regras continuam sem verificação. Manter sincronização na nuvem indisponível para uma distribuição pública até essa confirmação; o uso local do launcher não depende dela.
4. **Assinatura Authenticode e App Control:** os arquivos gerados localmente não têm assinatura Authenticode. Neste Windows, os eventos Code Integrity 3077 e 3033 bloquearam DLLs de teste não assinadas sob uma política User Mode Code Integrity em modo enforced. O build agora consegue assinar e validar os binários com um certificado de code signing confiável (RSA, 2048–4096 bits), e o workflow de release exige os secrets `POKEMONPLAY_SIGNING_PFX_BASE64` e `POKEMONPLAY_SIGNING_PFX_PASSWORD`. Eles ainda não estão configurados. Este dispositivo também exige que a política App Control confie no signatário; o administrador da política precisa aprovar o certificado/editor antes de executar o app. Não desative a política para contornar o bloqueio.

Depois de resolver e verificar os quatro itens, revisar a lista de assets, tornar o repositório público e testar o download da release sem autenticação em uma sessão anônima.
